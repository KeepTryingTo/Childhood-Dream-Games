# 中国象棋游戏 —— 需求与实现步骤文档

> 版本：v1.0 ｜ 日期：2026-08-30 ｜ 状态：需求评审

## 1. 项目概述

### 1.1 目标
实现一个规则完整、架构清晰、体验良好的中国象棋游戏，具备：
- 双人对战（本地）
- 人机对战（内置 AI，分难度）
- 完整规则引擎（含将军、将死、困毙、飞将等）
- 悔棋、存档、走子记录等辅助功能

### 1.2 技术选型（建议）

| 方案 | 技术栈 | 适用场景 |
|---|---|---|
| A（推荐） | HTML5 Canvas + JavaScript/TypeScript | 网页端，零安装易演示 |
| B | Python + Pygame | 桌面端，适合学习 |
| C | C++ / Qt | 高性能桌面端 |

说明：规则引擎与 AI 写成**纯逻辑模块**（不依赖 UI），可在任意平台复用、可单元测试。

## 3. 规则基线（实现依据）

### 3.1 棋盘与坐标
- 采用 `(row, col)`，row∈[0,9]，col∈[0,8]；row 0 为黑方底线，row 9 为红方底线。
- 河界：row 4 与 row 5 之间。
- 黑方九宫：row 0–2、col 3–5；红方九宫：row 7–9、col 3–5。

### 3.2 棋子走法

| 棋子 | 走法 | 限制 |
|---|---|---|
| 将/帅 | 横竖一格 | 不出九宫；双方将帅不得在同一条直线上直接对面（飞将） |
| 士/仕 | 斜一格 | 不出九宫 |
| 象/相 | 斜两格（田字） | 不能过河；田字中心有子则不能走（塞象眼） |
| 马 | 日字 | 前进方向相邻交叉点有子则不能走（蹩马腿） |
| 车 | 横竖任意距离 | 不能越子 |
| 炮 | 不吃子时同车；吃子时必须隔恰好一个子（炮架） | 不吃子不能越子 |
| 兵/卒 | 向前一格 | 过河后可横走一格；任何情况不能后退 |

### 3.3 将军与胜负
- 将军：一方走子后威胁对方将/帅。
- 走子后使己方将/帅被攻击、或将帅照面的走法为**非法着法**。
- 轮到走子的一方无任何合法着法：若被将军则为**将死**，否则为**困毙**，均判负。

## 4. 总体设计

### 4.1 分层架构
```
┌─ UI 层：渲染、输入、动画、音效
├─ 对局流程层：回合、悔棋、存档、记谱
├─ 规则引擎层：走法生成/校验、将军与胜负判定（纯逻辑）
├─ AI 层：局面评估 + 搜索
└─ 数据模型层：棋盘、棋子、着法、状态

```

### 4.2 数据模型
```js
// 棋子编码：0=空；红正黑负
// 1=将/帅 2=士 3=象 4=马 5=车 6=炮 7=兵/卒
board = 10x9 二维数组   // board[r][c]

move  = { from:{r,c}, to:{r,c}, piece, captured }

state = {
  board,
  turn: 'red' | 'black',
  history: [move, ...],
  status: 'playing' | 'red_win' | 'black_win'
}

```

## 5. 详细实现步骤

### 步骤 0：项目初始化（0.5 天）
1. 建立目录结构，搭建 index.html 与 Canvas 容器。
2. 确定模块组织方式（ES Module 或普通 script）。
3. 验收：页面显示空白画布，控制台无报错。

### 步骤 1：数据模型（0.5 天）
1. 实现 `model.js`：棋子编码常量、`initBoard()`、`cloneBoard()`。
2. 工具函数：`inBoard(r,c)`、`sideOf(piece)`、`inPalace(r,c,side)`、`hasCrossedRiver(r,side)`。
3. 验收：`initBoard()` 输出与 4.2 布局一致；克隆互不影响。

### 步骤 2：规则引擎 —— 伪合法走法生成（1.5 天）
在 `rules.js` 中按棋子类型生成"伪合法着法"（满足走子规则、暂不考虑将军）：
1. 将/帅、士：九宫内方向偏移枚举。
2. 象：四个斜向两格，检查象眼与河界。
3. 马：八个方向，检查蹩腿点。
4. 车：四方向直线扫描直至遇子。
5. 炮：移动同车；吃子时跳过恰好一个炮架后取第一个敌子。
6. 兵：按阵营与是否过河确定方向集合。
7. 汇总接口：`getPseudoMoves(board, r, c)`、`getAllPseudoMoves(board, side)`。
8. 验收：通过第 6 节构造用例。

### 步骤 3：规则引擎 —— 合法性过滤与胜负判定（1 天）
1. `isAttacked(board, r, c, bySide)`：判断某点是否受某方威胁。
2. 飞将检测 `kingsFacing(board)`。
3. `getLegalMoves`：对伪合法着法试走（makeMove/undoMove），过滤掉走完后己方将被攻击或将帅照面的着法。
4. `isChecked(board, side)`；无合法着法时判定将死/困毙。
5. 验收：牵制子不能动、飞将、经典杀局均判定正确。

### 步骤 4：UI 渲染（1 天）
1. `ui.js` 绘制棋盘：边框、网格、楚河汉界文字、九宫斜线、星位点。
2. 绘制棋子：圆形棋子面 + 红黑汉字。
3. 高亮渲染：选中子、可落点、上一步起止点、被将军的将/帅。
4. 适配高分屏（devicePixelRatio）与窗口缩放。
5. 验收：初始局面渲染正确、无错位。

### 步骤 5：交互与对局流程（1 天）
1. `game.js` 状态机：点己方子选中；点合法落点走子；点其他己方子换选。
2. 走子后：写入 history、切换回合、将军检测、胜负检测、通知 UI 重绘。
3. 悔棋、重新开局按钮。
4. 验收：完整双人局可下到将死/困毙，悔棋正确。

### 步骤 6：辅助功能（0.5–1 天）
1. 存档/读档：state 序列化 JSON 存 localStorage。
2. 走子记录列表展示（可扩展中文记谱，如"炮二平五"）。
3. 动画与音效（可选）。
4. 验收：刷新页面后可恢复对局。

### 步骤 7：AI 对战（2 天）
1. 评估函数 `evaluate(board)`：
   - 基础子力值：车 900、炮 450、马 400、象 200、士 200、兵 100（过河 200）
   - 叠加"子力位置价值表"（PST）修正位置好坏
2. 搜索：Negamax + α-β 剪枝；
   - 着法排序（吃子优先，MVV-LVA）提升剪枝效率
   - 可选：静止搜索消除水平线效应
   - 难度分级：易=深度1+随机扰动；中=深度2–3；难=深度4
3. 可选：Web Worker 中运行 AI，避免卡顿 UI。
4. 验收：AI 3 秒内出招，不走非法着法，会吃子、会应将。

### 步骤 8：测试、优化与发布（1 天）
1. 补齐第 6 节单元测试并修复缺陷。
2. 体验优化：提示文案（将军/将死/困毙）、按钮禁用态。
3. 编写 README（运行方式、功能列表、已知问题）。
4. 发布：静态托管（如 GitHub Pages）或打包桌面端。

## 8. 风险与注意事项
1. 规则细节（蹩马腿、炮架、飞将）极易出错，务必用单元测试验证，禁止只靠肉眼调试。
2. 困毙判负是中国象棋规则，与国际象棋的"逼和=和棋"不同，胜负判定不要写错。
3. AI 深度 ≥4 时 JS 性能吃紧，必须做剪枝与着法排序，否则界面卡顿。
4. 联机对战涉及同步、断线、判和协议，是独立子系统，建议列为二期目标。
