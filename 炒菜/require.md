# 🍳 炒菜游戏 - 初步需求文档 (require.md)

## 1. 游戏概述 (Game Overview)
- **游戏名称**：暂定《疯狂后厨》(Crazy Kitchen / Chef's Rush)
- **游戏类型**：时间管理 / 模拟经营 / 多人合作 (Time Management / Simulation / Co-op)
- **核心体验**：玩家需要在高压环境下，通过合理分配厨师角色、优化工作流程，完成顾客的点单需求，避免厨房混乱，最终获得高评分。
- **目标平台**：PC (Steam) / 移动端 (iOS/Android) / 网页端 (WebGL)

## 2. 核心玩法 (Core Gameplay)
游戏以“关卡制”或“无尽模式”为主。每一局游戏包含多个“订单波次”。
- **接单**：顾客下单，生成订单气泡（显示所需菜品及倒计时）。
- **备菜**：拿取食材 -> 清洗 -> 切配。
- **烹饪**：将食材放入锅/烤箱/炸炉，掌握火候与时间。
- **装盘与上菜**：将做好的菜装入干净盘子，送至出餐口。
- **清理**：回收脏盘子，清洗后循环使用。

## 3. 角色与职责设计 (Roles & Responsibilities)
游戏核心亮点在于“各种厨师”的分工协作。可设计为单人切换控制，或多人联机各自扮演。

| 角色名称 | 核心职责 | 动作/技能 | 升级/进阶方向 |
| :--- | :--- | :--- | :--- |
| **🔪 配菜师 (Prep Chef)** | 负责食材的初步处理 | 拿取、清洗、切菜、腌制 | 提升切菜速度、解锁高级刀工（如切丝/切块） |
| **🍳 主厨 (Head Chef)** | 负责核心烹饪与火候控制 | 翻炒、调味、控制火候、装盘 | 解锁新菜谱、减少烹饪时间、增加“完美烹饪”判定区间 |
| **🏃 跑堂/服务员 (Runner)** | 负责物流与清洁 | 端菜上桌、收回脏盘子、洗盘子、补充食材库存 | 提升移动速度、增加托盘容量（一次端多盘） |
| **📋 统筹/经理 (Manager)**| (可选) 负责全局调度 | 催促、加速特定厨师、使用全局道具（如“时间冻结”） | 增加顾客耐心、提升小费收入 |

## 4. 核心游戏机制 (Game Mechanics)

### 4.1 订单与顾客系统
- **耐心值**：每个订单有倒计时，超时会导致顾客生气，扣除大量分数甚至直接离店。
- **小费机制**：上菜越快、菜品完美度越高，获得的小费（游戏内金币）越多。
- **特殊顾客**：如“大胃王”（点巨量菜）、“挑剔客”（不能有任何失误）、“VIP”（给双倍钱但耐心极低）。

### 4.2 烹饪与物理交互
- **状态机系统**：食材具有状态（生 -> 半熟 -> 熟 -> 完美 -> 烧焦 -> 碳化）。
- **QTE/微操**：炒菜时可能需要简单的节奏点击（如翻炒动作）来提升菜品品质。
- **物理碰撞**：扔食材、滑盘子等趣味交互（类似《胡闹厨房》）。

### 4.3 厨房环境与动态事件
- **动态障碍**：厨房可能会发生突发状况，如“地板漏水（减速）”、“老鼠偷菜”、“烤箱起火（需要灭火器）”。
- **地形变化**：传送带厨房、移动餐车、冰川厨房（食材会冻住需要解冻）。

## 5. 关卡与进度系统 (Progression)
- **故事模式**：从路边摊 -> 快餐厅 -> 高级酒楼 -> 米其林三星 -> 太空餐厅。
- **解锁系统**：
  - 解锁新食材（如从白菜解锁到牛排）。
  - 解锁新厨具（如从平底锅解锁到高压锅）。
  - 解锁新厨师皮肤和厨房装修。

## 6. 美术与音效风格 (Art & Audio)
- **美术风格**：建议采用 **Low Poly（低多边形）** 或 **2D 卡通手绘** 风格。色彩明快，UI 清晰，强调动作的夸张和滑稽感。
- **音效设计**：
  - 极具反馈感的 ASMR 音效（切菜的“嚓嚓”声、炒菜的“滋啦”声、洗盘子的水声）。
  - 紧张的背景 BGM（随着订单增多，BGM 节奏加快）。
  - 角色语音（“订单来了！”、“菜要糊了！”、“让一让！”）。

## 7. 技术栈建议 (Technical Stack)
- **游戏引擎**：Unity (推荐，适合2D/3D及多平台发布) 或 Godot (开源轻量，适合2D)。
- **编程语言**：C# (Unity) 或 GDScript/C# (Godot)。
- **网络框架**（若做多人联机）：Photon (PUN) / Mirror / Netcode for GameObjects。
- **版本控制**：Git + Git LFS (用于管理美术和音频大文件)。

## 8. MVP (最小可行性产品) 第一阶段开发目标
为了快速验证核心玩法，第一阶段**仅实现以下内容**：
1. **单一场景**：一个基础厨房，包含冰箱、切菜板、炒锅、出餐台、水槽。
2. **单一角色**：玩家控制一个全能厨师（可移动、可交互所有物品）。
3. **基础流程**：拿取西红柿 -> 切菜板切块 -> 炒锅炒熟 -> 装盘 -> 放到出餐台。
4. **简单订单**：屏幕上方显示“需要一份炒西红柿”，完成后加分。
5. **失败条件**：菜品烧焦，或订单超时。

## 9.3 烹饪火候状态机（4.2 落地）

```
cooking: cookMs 0 → COOK_MS(3500ms，翻炒每次 +420ms，冷却 220ms)
done:    doneMs 计时
         [0, 1200ms)      → 出锅 quality='good'（略生）
         [1200, 3000ms]   → 出锅 quality='perfect'（火候刚好 ★）
         (3000, 7000ms]   → 出锅 quality='good'（过火）
         > 7000ms         → burnt 烧焦（不可装盘，只能出锅后丢垃圾桶）
```

## 9.4 交互规则表（interact 按最近工作站 + 手持物 + 工作站状态决定）

| 工作站 | 条件 | 动作 |
|---|---|---|
| 冰箱 | 空手 | 取当前选中食材（1~4 切换） |
| 砧板 | 手持 raw 食材 | 放上开始切（1300ms，可离开） |
| 砧板 | 空手 + 已切好 | 取走 chopped 食材 |
| 灶台 | 手持 chopped 食材 | 下锅（最多 3 种，可组合） |
| 灶台 | 空手 + 烹饪中 | **翻炒**（QTE：进度 +420ms，火花动画） |
| 灶台 | 空手 + 熟/烧焦 | 出锅（手持 dish / burnt） |
| 装盘台 | 手持 dish(good/perfect) 且有干净盘 | 装盘（消耗 1 干净盘） |
| 出餐台 | 手持 plated | 匹配订单上菜（挑剔客拒收非完美） |
| 水槽 | 手持脏盘 | 放入清洗（3000ms，完成后自动回干净盘栈） |
| 垃圾桶 | 手持任何物品 | 丢弃 |

## 9.5 计分与难度（无尽模式）

- 单盘结算：`base × (perfect?1.5:1) × (vip?2:1) + tip`，`tip = base × 0.5 × 耐心剩余比例 × (vip?2:1)`
- 大胃王需 2 盘（每盘独立结算，耐心 160%）；VIP 耐心 50%；挑剔客只收 perfect
- 订单节奏：首单 3s；间隔 `max(7, 16 - elapsed/40)s`；并行上限 `min(6, 3 + elapsed/45)`
- 耐心系数随时间衰减至 55% 下限；特殊顾客概率随时间上升
- 上菜 8s 后回收台出现脏盘；初始干净盘 5 只
- 3 心：订单超时 -1，扣完 → 结束，按模式持久化最高分

# 10. v2.0 全自动协作模拟（方向调整）

> **需求变更**：游戏从"玩家操作的单人厨房"调整为**全自动观赏模拟**——厨房里有切菜的、炒菜的、端盘子的，还有一位经理；顾客坐桌点单，菜做好后由跑堂**送到顾客的桌子上**；全场角色自动协作运转，**无需玩家操作**。玩家身份为"店长观战"：可暂停、调速（1x/2x/4x）。

## 10.1 场景布局（世界 1180×680，左餐厅右厨房）

```
┌─────────── 餐厅区 ───────────┐┌─ 传菜口 ─┐┌────────── 厨房区 ──────────┐
│  🪑T1          🪑T2          ││  取餐台  ││  装盘台      灶台(主厨)     │
│                             ││ (跑堂)  ││      备菜台    🍳           │
│  🪑T3          🪑T4          ││         ││  水槽   垃圾桶   冰箱      │
│  🚪门(顾客出入)              ││         ││      砧板(配菜师)          │
└─────────────────────────────┘└─────────┘└────────────────────────────┘
```

- 4 张餐桌（顾客 1 人 1 桌），门在餐厅左下，顾客进门 → 走到空桌 → 点单
- 传菜口（取餐台）是厨房与餐厅的衔接点：主厨把装盘菜放这里，跑堂从这里取菜送桌

## 10.2 角色与自动状态机（FSM）

| 角色 | 速度 | 状态机 | 手持 |
|---|---|---|---|
| 🔪 配菜师 | 150 | 待命 → 去冰箱 → 取食材(0.4s) → 去砧板 → 切配(1.5s) → 送备菜台 → 待命 | 食材/切好食材 |
| 🍳 主厨 | 140 | 待命 → 取备菜（按订单组合）→ 下锅 → 翻炒（每 0.9s 一铲加速）→ **等完美窗口自动出锅** → 装盘 → 放取餐台 → 待命 | 食材组/菜/装盘菜 |
| 🏃 跑堂 | 190 | 待命 → 取餐台端菜 → 送到顾客桌 → （无菜时）收桌上脏盘 → 送水槽 → 待命 | 装盘菜/脏盘 |
| 👔 经理 | 120 | 巡逻（随机走点+驻足）→ 每 7~12s **催促**一名在岗员工（速度 ×1.35 持续 4s，💢 特效） | — |

- 配菜策略：按订单队列 FIFO 补缺——备菜台缺哪种食材就切哪种（每种上限 4 防囤积），不缺则待命
- 主厨出锅时机：火候环黄色完美窗口（熟后 1.2~3s），模拟里主厨是专业的，基本全完美；备菜台有料时可提前取下一单食材（流水线并行）
- 跑堂优先级：上菜 > 收脏盘 > 待命；一次一盘
- 装盘消耗干净盘（初始 6），跑堂洗盘回栈（水槽 3s 自动完成）形成闭环

## 10.3 顾客状态机

```
进门 → 走到空桌 → 坐下(1s) → 点单(气泡显示菜品+耐心环)
     → 等菜(耐心倒计时，超时→生气离开，差评)
     → 上菜 → 用餐(10s) → 付款(1.5s，+营业额飘字) → 离开 → 桌上留脏盘
```

- 顾客到达：每 8~14s 一位（有空桌才生成），随时间客流渐密
- 特殊顾客：👑VIP（10%，收入 ×2，耐心 ×0.6）、😋大胃王（8%，连点 2 道菜）
- v1.0 的挑剔客在全自动模式下无意义（主厨恒定完美出手），移除

## 10.4 计分与观赏控制

- 统计面板：营业额、服务/流失顾客、好评率、平均等菜时长、各类菜销量
- 单份收入 = 菜价 × 完美(×1.5) × VIP(×2) + 小费(菜价 × 0.5 × 剩余耐心比)
- 玩家控制（非游戏操作）：空格暂停 · 1/2/3 或按钮调速 1x/2x/4x · R 重开
- 无失败条件：无尽模拟经营观赏（超时顾客只影响好评率统计）

# 11. v3.0 长线体验与视觉升级

> **需求变更**：在全自动模拟核心之上增加——小人化角色、厨房装修装扮、动态环境事件、季节/节日主题、成就图鉴、本地荣誉榜（异步好友的零依赖落地）、UI 动效与新手引导。说明：本项目为纯前端零依赖网页，"异步好友互助"裁剪为**本地荣誉排行榜 + 跨局累计目标**（无后端，不伪造网络功能）。

## 11.1 角色小人化

角色由"圆球"升级为**小人**：头（肤色）+ 头发 + 身体（衬衫/围裙/领带）+ 双腿行走摆动 + 双臂反向摆动 + 厨师帽。每个实体拥有由 id 派生的**稳定外观**（肤/发色），VIP 顾客金发。行走相位按移动距离累计（停步自然并拢）。

## 11.2 厨房装修主题（装扮系统）

4 套主题（localStorage 持久化，切换即时生效）：暖木小馆 / 青花雅苑 / 夜市霓虹 / 马卡龙屋——影响厨房地砖、隔断墙、桌布配色；餐厅地板色由**季节**叠加。

## 11.3 季节与节日

- 四季（春🌸/夏🌞/秋🍂/冬❄）每 3 分钟自动轮换，可手动切换；影响餐厅地板色调 + 全屏飘落粒子（花瓣/绿叶/落叶/雪花）
- 节日彩蛋：按系统日期匹配（元旦/劳动节/国庆/圣诞），顶部横幅显示"××特惠"
- 四季全经历解锁「四季餐馆」成就

## 11.4 动态环境事件（v0.1 §4.3 落地）

| 事件 | 行为 | 处理 |
|---|---|---|
| 🐭 老鼠 | 从右侧潜入 → 走向备菜台 → 停留 2.5s 偷 1 份切好食材 → 逃离 | 经理靠近（55px）即驱散；未赶到则失窃 |
| 💧 漏水 | 厨房随机区域水渍，半径 75px 内员工减速 45% | 经理走至水渍修理 2.5s |
| 🔥 灶火 | 灶台蹿火苗，主厨避让不接新单 | 经理灭火 2.5s |

- 调度：开局 50s 后，每 45~80s 掷骰（35% 不触发；鼠 45%/漏 20%/火 15%，火需灶台空闲）；同时至多 1 起
- 经理 FSM 新增 `toEvent → fixing`（事件优先于巡逻催促）；事件计数进入成就与统计

## 11.5 成就与图鉴（跨局持久化）

- **13 项成就**：单局类（完美主义/财源广进/满堂彩）+ 累计类（百炼成厨/灭鼠英雄/消防队员/全菜谱大师/四季餐馆等）
- **图鉴**：菜品图鉴（3 道，出品计数点亮）+ 顾客图鉴（普通/VIP/大胃王，接待计数点亮）
- 达成时右上角 toast 弹出 + 上行琶音音效；每 8 秒巡检 + 打烊结算时终检
- 累计数据由 `achievements.mergeHistory` 在打烊时合并入 localStorage

## 11.6 荣誉榜与打烊结算

- 「🌙 打烊结算」按钮：暂停 → 合并累计 → 成就终检 → 记录榜单 → 结算面板（营业额/是否新高/新成就/榜单名次）
- 本地荣誉榜 top10（昵称 + 营业额 + 上菜数 + 日期），昵称可自定义（≤12 字）

## 11.7 UI 动效 / 音效 / 新手引导

- 数字变化弹跳（scale 动画）、toast 滑入滑出、面板 tab 渐入、按钮 hover 浮起
- 新增音效：成就琶音、事件警报、修复提示、季节风铃、打烊铃
- 新手引导：首访 5 步引导条（自动 8s/步，可跳过），localStorage 记忆；设置面板可重看

# 12. v3.1 场景规则与空间合理性（问题修复轮）

> **需求变更**：修复用户指出的场景不合理——①顾客站到桌中央 ②厨房与餐厅之间没有门（直接穿墙）③员工直接穿过备菜台等实体 ④桌子没有椅子。并配套引入导航与碰撞系统。

## 12.1 座位系统（顾客坐椅子）

- 每张餐桌配 **4 把椅子**（相对桌心偏移 ±58px：上/下/左/右），渲染含座面与靠背，被占用时高亮
- 顾客进店时随机分配座位，`entering` 目标从"桌心"改为**椅子坐标**，坐姿面向桌子
- 跑堂送菜/收盘使用**服务位**（桌右侧 +80px，避开椅子）

## 12.2 双门通道

- 隔断墙（x∈[600,614]）改为**三段墙体 + 两扇门**：北门"传菜口"（y 160~260）、南门"员工通道"（y 440~540），渲染门框/双开页/地垫/门名
- **跨区导航**：移动起终点分居墙两侧时，经"门厅路点"三段导航（厨房侧点 → 餐厅侧点 → 目标），穿墙段 y 恒在门缺口内；北门厨房侧点 (725,210) 偏右避开取餐台
- 墙体为碰撞体，实体无法穿越

## 12.3 碰撞避障

- **障碍集合**：8 个厨房台面 AABB + 3 段墙体 AABB + 4 张餐桌 AABB
- **圆-AABB 推离**：实体（半径 9）进入障碍即推至最近表面外，配合速度切向分量实现"贴边滑移绕行"
- **防卡死三层保险**：
  1. 配菜师三条动线预设绕行路点（砧板↔冰箱、砧板→备菜台走侧走廊，避开正对台面的垂直卡死）
  2. 通用卡死逃逸：有目标却停滞 1.2s → 左右交替侧向绕行点（超时 2.2s 自动换边）
  3. 交互站位全部外移至距台面 ≥15px（原 60px 偏移全部校验为可达）
- 布局调整：水槽 (950,560)→(980,560)，与砧板间留出 50px 侧走廊

## 12.4 数值补偿

绕行使动线变长（首轮 e2e 好评率 87%），基础耐心 75s→85s 补偿，回归 100% 好评。
