# 贪吃蛇游戏 —— 需求与实现步骤文档

> 版本：v1.0 ｜ 日期：2026-08-30 ｜ 状态：需求评审

## 1. 项目概述

### 1.1 目标
实现一个规则完整、架构清晰、体验流畅的经典贪吃蛇游戏，具备：
- 单人闯关（核心玩法）
- 可调节难度（速度 / 地图大小 / 障碍）
- 计分、最高分记录、暂停、重开
- 可选：穿墙模式、双人对战、AI 自动寻路

### 1.2 技术选型（建议）

| 方案 | 技术栈 | 适用场景 |
|---|---|---|
| A（推荐） | HTML5 Canvas + JavaScript/TypeScript | 网页端，零安装易演示 |
| B | Python + Pygame | 桌面端，适合学习 |
| C | C++ / SFML | 高性能桌面端 |

说明：游戏逻辑写成**纯逻辑模块**（不依赖 UI），可独立运行、可单元测试；UI 仅负责渲染与输入。

### 2.3 非功能需求
- 逻辑与 UI 分离：`SnakeGame` 类无 DOM/Canvas 依赖

## 3. 规则基线（实现依据）

### 3.1 坐标系
- 网格 `(row, col)`，row∈[0,H-1]，col∈[0,W-1]；(0,0) 为左上角。
- 方向向量：上 (-1,0)、下 (1,0)、左 (0,-1)、右 (0,1)。

### 3.2 移动与生长
- 每个 tick：根据方向计算新头部 = 旧头部 + 方向向量。
- 若新头部 == 食物：不移除尾部（蛇长 +1），刷新食物，加分。
- 否则：移除尾部（蛇长不变），头部入队。
- 注意：**先判碰撞再移动**，且"撞自身"判断时不应把即将移除的尾节算作障碍（除非本 tick 吃食物不移除尾部）。

### 3.3 碰撞规则
- 撞墙：新头部越界 → 死亡（穿墙模式下改为取模绕回）。
- 撞自身：新头部 ∈ 当前蛇身（按 3.2 的尾节处理）→ 死亡。

### 3.4 输入防抖（关键易错点）
- 同一 tick 内多次按键只生效一次方向变更，且**禁止 180° 反向**（如正向右时按左无效）。
- 用"下一帧待应用方向"缓冲，避免一帧内连按两次导致自杀。

## 4. 总体设计

### 4.1 分层架构
```
┌─ UI 层：Canvas 渲染、键盘输入、HUD、菜单
├─ 游戏流程层：开始/暂停/结束、难度、计分、最高分
├─ 逻辑引擎层：SnakeGame（纯逻辑，可测试）
└─ 数据模型层：蛇体队列、食物、方向、状态

```

### 4.2 数据模型
```js
direction = { r: -1, c: 0 }          // 当前方向
snake     = [ {r,c}, {r,c}, ... ]    // 队首=头
food      = { r, c }
state = {
  snake,
  direction,
  nextDirection,   // 输入缓冲
  food,
  score,
  status: 'ready' | 'playing' | 'paused' | 'over',
  speedMs          // 每 tick 毫秒数
}

```

## 5. 详细实现步骤

### 步骤 0：项目初始化（0.5 天）
1. 建立目录结构，搭建 index.html 与 Canvas 容器、HUD（分数/最高分/状态）。
2. 确定模块组织方式（ES Module 或普通 script）。
3. 验收：页面显示空白画布与 HUD，控制台无报错。

### 步骤 1：数据模型与逻辑引擎骨架（0.5 天）
1. `game.js` 实现 `SnakeGame` 类：构造时初始化蛇体（居中、朝右、长度 3）、随机食物、状态 `ready`。
2. 工具函数：`inBoard(r,c)`、`equals(a,b)`、方向常量表、反向判定。
3. 验收：`new SnakeGame(20,20)` 后蛇体、食物、状态符合预期；食物不在蛇身上。

### 步骤 2：核心逻辑 —— 移动、吃食、碰撞（1.5 天）
1. `setDirection(dir)`：写入 `nextDirection`，过滤 180° 反向。
2. `tick()`：
   - 应用 `nextDirection` → `direction`
   - 计算新头部
   - 撞墙判定（含穿墙分支）
   - 撞自身判定（注意尾节处理）
   - 吃食物分支 vs 普通移动分支
   - 更新分数 / 刷新食物
3. `spawnFood()`：在空格中随机选点；空格过少时可枚举所有空位避免死循环。
4. 验收：通过第 6 节 T1–T8。

### 步骤 3：游戏循环与输入（1 天）
1. `main.js` 用**固定时间步**驱动：累计 elapsed，达到 `speedMs` 才调用一次 `tick()`；渲染用 `requestAnimationFrame` 独立进行。
2. 键盘监听：方向键/WASD → `setDirection`；空格 → 暂停/继续；R → 重开。
3. 状态机：`ready`（按任意方向开始）→ `playing` ⇄ `paused` → `over`（可重开）。
4. 验收：速度稳定；连按不会自杀；暂停时逻辑不推进。

### 步骤 4：UI 渲染（1 天）
1. `ui.js` 绘制网格背景、蛇身（头/身区分色）、食物、障碍。
2. HUD：当前分、最高分、状态文字（READY / PAUSED / GAME OVER）。
3. 适配高分屏（devicePixelRatio）与窗口缩放；格子像素 = canvasSize / 格数。
4. （可选）平滑移动：在两个 tick 间对蛇头做线性插值。
5. 验收：渲染无错位，头身食物颜色分明。

### 步骤 5：计分、最高分与难度（0.5–1 天）
1. 吃食物 +10 分；实时更新 HUD。
2. `storage.js`：读写 localStorage（key 如 `snake_best`），开局加载、死亡时更新。
3. 难度：简单 150ms/20×20、中等 100ms/25×25、困难 70ms/30×30；菜单切换并重置。
4. （可选）加速机制：每吃 5 个食物 `speedMs *= 0.92`，设下限。
5. 验收：刷新页面最高分保留；切难度速度与地图正确。

### 步骤 6：扩展功能（按需，1–2 天）
1. 穿墙模式开关。
2. 障碍物：开局随机/固定布墙，渲染并纳入撞墙判定。
3. 特殊食物：定时刷新，效果（加分/减速/缩身）限时。
4. 音效（Web Audio 或 `<audio>`）。
5. 验收：各扩展开关独立生效，不破坏基础玩法。

### 步骤 7：AI 自动寻路（可选，1–2 天）
1. BFS 求"头→食物"最短路，逐步执行。
2. 安全性检查：走一步后用 BFS/ flood fill 确认蛇尾仍可达，避免把自己困死。
3. 进阶：Hamilton 回路保证不死但较慢；或 A* + 虚拟模拟。
4. 验收：AI 能稳定吃食物，简单图下长时间不死。

### 步骤 8：测试、优化与发布（1 天）
1. 补齐第 6 节单元测试并修复缺陷。
2. 体验优化：移动端滑动控制、按钮禁用态、死亡弹窗。
3. 编写 README（运行方式、操作说明、规则、已知问题）。
4. 发布：静态托管（如 GitHub Pages）或打包桌面端。

## 8. 风险与注意事项
1. **逻辑与渲染帧率解耦**：若直接用 `requestAnimationFrame` 当逻辑帧，不同显示器速度不一致；必须用固定时间步累加器。
2. **输入缓冲与反向禁止**：一帧多键、180° 反向是经典自杀 bug，务必用 `nextDirection` 缓冲 + 反向过滤，并单测。
3. **碰撞判定的尾节陷阱**：普通移动时尾部本 tick 会让出位置，不应被判为撞自身；吃食物不移除尾部时则要算上。
4. **食物生成的死循环**：蛇几乎占满棋盘时纯随机可能久找不到空位，应改为收集空位列表随机选取，并对"已满盘"做胜利/结束处理。
5. **穿墙与障碍的组合**：穿墙模式下障碍物仍可致死，需明确规则并在 UI 说明。
6. **AI 困死**：朴素 BFS 追食物容易把自己围死，必须加可达性/安全性检查。
