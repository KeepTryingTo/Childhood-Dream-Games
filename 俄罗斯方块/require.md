# 网页版俄罗斯方块 —— 需求与实现步骤文档

> 版本：v1.0 ｜ 日期：2026-08-30 ｜ 状态：需求评审

## 1. 项目概述

### 1.1 目标
实现一个规则完整、架构清晰、体验流畅的经典俄罗斯方块游戏，具备：
- 单人模式（核心玩法）
- 多难度选择（速度 / 方块下落速度递增）
- 计分、等级、最高分记录、暂停、重开
- 可选：幽灵方块（Shadow/Ghost Piece）、硬降（Hard Drop）、下一个方块预览、暂停、音效

### 1.2 技术选型（建议）
| 方案 | 技术栈 | 适用场景 |
|---|---|---|
| A（推荐） | HTML5 Canvas + JavaScript/TypeScript | 网页端，零安装易演示 |
| B | Python + Pygame | 桌面端，适合学习 |
| C | C++ / SFML | 高性能桌面端 |

说明：游戏逻辑写成**纯逻辑模块**（不依赖 UI），可独立运行、可单元测试；UI 仅负责渲染与输入。

## 3. 规则基线（实现依据）

### 3.1 坐标系
- 网格 (row, col)，row ∈ [0, 19]（从上到下），col ∈ [0, 9]（从左到右）。
- 方块坐标以**左上角锚点**为基准，偏移量定义各子块相对位置。

### 3.2 七种方块定义
| 方块 | 形状（4×4 矩阵） | 颜色 |
|---|---|---|
| I | [[1,1,1,1]]（水平）/ 竖排 4×1 | 青色 |
| O | [[1,1],[1,1]]（2×2，不旋转） | 黄色 |
| T | [[0,1,0],[1,1,1]] | 紫色 |
| S | [[0,1,1],[1,1,0]] | 绿色 |
| Z | [[1,1,0],[0,1,1]] | 红色 |
| J | [[1,0,0],[1,1,1]] | 蓝色 |
| L | [[0,0,1],[1,1,1]] | 橙色 |

### 3.3 旋转与踢墙（Wall Kick）
- 顺时针旋转：对 4×4 矩阵做转置后每行反转。
- 踢墙：旋转后若与已锁定方块或边界碰撞，尝试水平偏移（左/右 1~2 格）和垂直偏移（上 1 格）来容纳旋转。
- 标准 SRS（Super Rotation System）踢墙表：
  | 旋转前→后 | 左踢 | 右踢 | 上踢 |
  |---|---|---|---|
  | 0→R | (0,0) | (-1,0),(-1,-1),(0,2),(-1,2) | ... |
  （具体表可参考标准 SRS 文档，初版可简化为偏移 ±1 格试探）

### 3.4 计分规则（经典 NES 计分）
| 消行数 | 分数 |
|---|---|
| 1 行 | 100 × 等级 |
| 2 行 | 300 × 等级 |
| 3 行 | 500 × 等级 |
| 4 行（Tetris） | 800 × 等级 |
| 软降每格 | 1 × 等级 |
| 硬降 | 2 × 等级 |

### 3.5 等级与速度
- 每消 10 行升 1 级。
- 等级 N 对应的下落间隔（毫秒）：max(100, 800 - (N - 1) * 50)，即最低 100ms/格。

## 4. 总体设计

### 4.1 分层架构
```
┌─ UI 层：Canvas 渲染、键盘输入、HUD、菜单
├─ 游戏流程层：开始/暂停/结束、难度、计分、最高分
├─ 逻辑引擎层：TetrisGame（纯逻辑，可测试）
│   ├─ 方块管理：生成、旋转、移动、锁定
│   ├─ 碰撞检测：边界 + 已锁定方块
│   ├─ 消行：全行检测 + 消除 + 上方下落
│   └─ 计分与等级
└─ 数据模型层：网格、方块、状态
```

### 4.2 数据模型
```js
// 网格：20行 × 10列，0=空，1~7=对应方块颜色索引
grid = [[0,...,0], ...]  // 20 个子数组

// 方块
piece = {
  type: 'I'|'O'|'T'|'S'|'Z'|'J'|'L',
  rotation: 0,           // 0,1,2,3
  position: { row, col }, // 锚点位置
  shape: [[1,...],...]   // 当前旋转状态的矩阵
}

// 游戏状态
state = {
  grid,
  currentPiece,
  nextPieces: [piece, piece, ...],  // 预览队列
  holdPiece,
  score,
  level,
  linesCleared,
  status: 'ready' | 'playing' | 'paused' | 'over'
}
```

### 4.3 7-Bag 随机生成器
- 每次生成 7 个方块放入队列，打乱顺序。
- 队列空时再生成新的 7 个。
- 保证每 7 个中每种方块恰好出现一次，避免连续重复。

### 4.4 文件结构（Web 版示例）
```
tetris/
├── index.html
├── require.md              # 本文档
├── css/style.css
├── js/
│   ├── model.js            # 方块定义、7-bag 随机器
│   ├── rules.js            # 碰撞/旋转/踢墙/消行（纯逻辑、可测试）
│   ├── game.js             # TetrisGame 主引擎
│   ├── ui.js               # Canvas 渲染
│   ├── input.js            # 键盘输入处理
│   ├── storage.js          # 最高分持久化
│   └── main.js             # 入口、游戏循环
└── tests/rules.test.js     # 单元测试
```

## 5. 详细实现步骤

### 步骤 0：项目初始化（0.5 天）
1. 建立目录结构，搭建 index.html 与 Canvas 容器、HUD（分数/等级/行数/下一个方块预览区域）。
2. 确定模块组织方式（ES Module 或普通 script）。
3. 验收：页面显示空白画布与 HUD，控制台无报错。

### 步骤 1：数据模型与方块定义（0.5 天）
1. model.js 定义 7 种方块的初始形状矩阵（0 旋转状态）及颜色。
2. 实现旋转函数 rotate(shape)：转置 + 每行反转。
3. 实现 7-bag 随机器 createBag()：返回打乱的 7 个方块类型数组。
4. 验收：每种方块旋转 4 次后回到初始状态；7-bag 保证每种恰好出现一次。

### 步骤 2：碰撞检测与移动（1 天）
1. isValid(grid, shape, row, col)：检查方块所有非零格子是否在网格内且未与已锁定方块重叠。
2. moveLeft/Right/Down：调用 isValid 判断是否可移动。
3. hardDrop：不断下移直到碰撞，返回最终行号。
4. lock(grid, piece)：将方块写入网格，返回被锁定的格子集合。
5. 验收：通过第 6 节 T1–T6。

### 步骤 3：旋转与踢墙（1 天）
1. 实现 rotateWithKick(grid, piece)：
   - 计算新旋转状态的形状。
   - 按踢墙表尝试偏移（原点 → 偏移列表逐项试探）。
   - 首项成功即返回新状态；全部失败则旋转被拒绝。
2. 简化版：先实现无踢墙的旋转，再逐步加入 ±1/±2 水平偏移试探。
3. 验收：通过第 6 节 T7–T8（旋转不穿墙、不重叠）。

### 步骤 4：消行与计分（1 天）
1. clearLines(grid)：
   - 扫描每行是否全满（无 0）。
   - 消除满行，上方整行下移（从消行处上方逐行下移填充）。
   - 返回消除的行数。
2. 计分：按 3.4 规则计算分数，更新等级与消行数。
3. 等级提升：每 10 行升 1 级，更新下落间隔。
4. 验收：通过第 6 节 T9–T10。

### 步骤 5：游戏循环与输入（1 天）
1. game.js 实现 TetrisGame 类：
   - spawnPiece()：从 7-bag 队列取方块，放在顶部中间；队列空则生成新 bag。
   - checkGameOver()：新方块生成位置即碰撞 → 游戏结束。
   - tick()：方块下移一格，不可移动则锁定 → 消行 → 生成新方块。
2. 固定时间步驱动：累计 elapsed，达到下落间隔才调用 tick()；渲染用 requestAnimationFrame 独立进行。
3. 键盘监听：← → 移动、↑ 旋转、↓ 软降、空格 硬降、P 暂停、R 重开。
4. 输入防抖：同一 tick 内多次按键只生效一次（用 nextAction 缓冲）。
5. 验收：速度稳定；旋转/移动/硬降正常；暂停时逻辑不推进。

### 步骤 6：UI 渲染（1 天）
1. ui.js 绘制：
   - 网格背景线（10×20）。
   - 已锁定方块（填充色 + 边框）。
   - 当前方块（填充色 + 边框）。
   - HUD：分数、等级、消行数、下一个方块预览（小网格绘制）。
2. 适配高分屏（devicePixelRatio）与窗口缩放。
3. （可选）幽灵方块：计算硬降落点，半透明绘制。
4. 验收：渲染无错位，颜色分明，预览区域正确。

### 步骤 7：Hold / 储存与扩展功能（0.5–1 天）
1. Hold 机制：按 C 键将当前方块暂存到 holdPiece，下次按 C 换回（每轮仅切换一次）。
2. 音效：使用 Web Audio API 或简单 <audio> 标签播放合成音效。
3. 消行动画：消行时闪烁若干帧后再移除，提升视觉反馈。
4. 验收：Hold 切换正确，不破坏游戏状态。

### 步骤 8：持久化、优化与发布（1 天）
1. storage.js：localStorage 存最高分、等级偏好。
2. 响应式：桌面端双栏布局（主棋盘 + 侧边栏）；移动端竖排 + 触摸按钮。
3. 编写 README（运行方式、操作说明、规则说明）。
4. 发布：静态托管（如 GitHub Pages）。
5. 验收：Chrome/Edge/Safari/Firefox 可用；最高分刷新后保留。

## 8. 风险与注意事项

1. **踢墙实现复杂度**：标准 SRS 踢墙表较繁琐，初版可简化为 ±1/±2 水平偏移试探，后续再补全标准表。
2. **旋转后穿模**：必须确保旋转后的每一个子块都不与已锁定方块或边界重叠，否则会出现"穿墙"视觉 bug。
3. **7-bag 实现**：不要使用纯随机 Math.random() * 7 | 0，必须用 7-bag 算法保证均匀分布，否则玩家会抱怨"一直不出某块"。
4. **消行后上方下落**：消行后必须从消行处的上一行开始逐行下移，不能简单地"删行再 unshift 空行"——因为中间可能有空行。
5. **游戏结束判定**：不是"方块碰到顶部"，而是"新方块生成位置即与已有方块碰撞"。O 方块（2×2）在顶部两行已满时最容易触发此判定。
6. **硬降与软降的区分**：硬降应瞬间完成（不经过中间帧），软降则逐格加速；两者计分不同。
7. **Hold 机制**：每轮只能切换一次 Hold，切换后当前方块变为 Hold 中保存的方块，且不计入旋转/移动次数。
8. **性能**：10×20 网格极小，无需优化；但若加幽灵方块，需额外计算硬降落点（逐格下移检测）。
